# Plan for WMHA-0045

## Current state verified

- `_raise_for_status` already has the exact mechanism needed: `authentication_required=False`
  turns `401` into `WindmillAuthorizationError` instead of `WindmillAuthenticationError`
  (`custom_components/windmill/api.py:813-822`). It is currently used only for the public
  coarse-health probe, and its message calls that case "the public probe".
- `async_list_workspaces` (`api.py:534-541`) calls `_raise_for_status` with the strict
  default, so Windmill Cloud's `401` becomes an authentication failure.
- `_async_validate_instance` (`config_flow.py:398-433`) already falls back to manual
  workspace entry for `WindmillAuthorizationError`, `WindmillNotFoundError`,
  `WindmillProtocolError` and `WindmillRequestError`. Only the explicit
  `except WindmillAuthenticationError` ahead of it forces `invalid_auth`.
- `_probe` (`api.py:657-694`) re-raises `WindmillAuthenticationError` and maps
  `WindmillAuthorizationError` to `UNAUTHORIZED`/`PERMISSION_DENIED` — already the wanted
  outcome once the status mapping is corrected at the call site.
- `_probe_json_object` and `_probe_json_list` (`api.py:1259-1313`) call `_raise_for_status`
  with the strict default and have no way to relax it per endpoint.
- `async_discover_capabilities` (`api.py:1037-1105`) probes two instance-scoped endpoints,
  `/api/health/detailed` and `/api/workers/list`, plus four workspace-scoped ones.

The correct fix is therefore a status-mapping correction at four instance-scoped call sites,
not new error types and not a config-flow rewrite.

## Failure modes and rollback

- Relaxing `401` too widely would hide a genuinely revoked token. Mitigated by scoping the
  change to instance-scoped call sites and keeping `whoami` and the workspace-scoped probes
  strict, each covered by a test.
- An invalid token now fails one step later. Accepted and recorded in the ticket; the error
  shown is still `invalid_auth` against the canonical `whoami` call.
- Rollback is a revert of a single commit; no persisted state or config-entry schema changes.

## Security and privacy review

- Credentials: transport unchanged, header-only `Authorization: Bearer <token>`. No token
  reaches logs, diagnostics, entity state or a URL. Test tokens stay obviously fake.
- Sensitive payloads: none added; probes keep discarding response rows.
- Permissions: strictly widens which tokens are accepted for setup. It grants no new access —
  Windmill still enforces every scope, and instance-scoped features remain unavailable for
  these tokens.
- Network exposure: no new endpoint, no new request.
