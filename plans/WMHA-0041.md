# Plan for WMHA-0041

## Current state verified

- The runnable selection already exists and is resolved: `load_selections` reads
  `OPT_RUNNABLES`, and `WindmillRunnableCoordinator` turns each selection into a
  `ResolvedRunnable` with `available` and `details` (`coordinator.py:590`).
- Every entity currently hangs off one service device built by `build_device_info`
  (`entity.py:17`). There is no per-subject device yet; worker entities use one device with a
  `_subject` suffix in the unique id.
- `WindmillRunCoordinator._observe` already parses the full job window but keeps only
  aggregates; the parsed rows are discarded (`coordinator.py:494`).
- `_feature_defaults` indexes `supported[key]` for every entry of `FEATURE_OPTIONS` while
  `_feature_capabilities` returns five of the seven keys (`config_flow.py:129`). It survives
  only because `FEATURE_DEFAULTS[key] and …` short-circuits on a false default.
- `WMHA-0040` verified that `jobs/list?script_path_exact={path}` keeps the union, so one
  request answers history, running state and (for `WMHA-0042`) the next run.

## Failure modes and rollback

- **The fast tier starves the slow tier.** `async_set_updated_data` reschedules the refresh
  timer, so a 60-second fast update would push the 5-minute exact read forever into the future.
  Mitigation: the fast tier assigns `self.data` and calls `async_update_listeners()`, which
  notifies entities without touching the schedule. This is the one non-obvious detail of the
  design and must stay covered by a test.
- **Request burst at setup.** The first refresh performs one request per selection, up to 25.
  Accepted: it happens once per reload, and the cap is the existing selection cap.
- Rollback is a revert; the feature is additive and default-off.

## Security and privacy review

- Credentials: unchanged; the new read uses the existing authenticated client.
- Sensitive payloads: the response also carries `permissioned_as`, `email`, `canceled_by`,
  `tag`, `labels` and `mem_peak`. The existing `_parse_job` allowlist drops all of them, and
  `include_args` is never sent, so `args` stays null.
- Permissions: none beyond the `jobs:read` the run observation already needs.
- Network exposure: none.
