## Guardrail design

`tickets/done/` is append-only and this ticket may not edit WMHA-0026/0029, so a strict check would
fail on exactly the two tickets it was written for. The check therefore carries an explicit,
commented grandfather set naming those two ids and pointing at WMHA-0034 as their correction
record. Every future done ticket must fill the section.

## Validation

| Check | Command | Expected |
| --- | --- | --- |
| Guardrails | `python scripts/validate_repository.py` | exit 0 |
| Guardrail is load-bearing | temporary "pending" in a non-exempt done ticket | validation fails |
| Whitespace | `git diff --check` | exit 0 |
| Tests | `uv run pytest -q` | unchanged pass count (no production code touched) |

## Failure modes

- A claim that rests only on the deleted disposable instance cannot be re-derived → record it as
  unverified rather than inferring it; escalate only if it is load-bearing for a published promise.
- The grandfather set could be used to exempt future tickets → it is a literal id set with a
  comment tying it to this ticket, not a pattern.
