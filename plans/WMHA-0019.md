# Plan for WMHA-0019

## Current state verified

- `custom_components/windmill/services.py:91` starts the runnable and then tracks the returned
  identifier inline inside the `windmill.run` handler.
- `custom_components/windmill/button.py:73` calls the same `async_start_runnable` helper and drops
  the identifier, so a button-started job never reaches `StartedJobRegistry`.
- `StartedJobRegistry.async_track` (`coordinator.py:583`) prunes and writes the whole registry under
  one lock, so the size and age bounds hold for any additional caller without change.
- A failing track currently propagates out of the action, so a persistence failure would be reported
  as a failed start although the job is already running.

## Proposed changes

| File or component | Change | Acceptance criterion |
| --- | --- | --- |
| `services.py` | Add `async_start_and_track_runnable`, the single start path that starts and then records the job | Registry entry after a button press; one shared path |
| `services.py` (`async_run`) | Call the shared helper instead of tracking inline | Bounds unchanged, metadata projection unchanged |
| `button.py` (`async_press`) | Call the shared helper | Button jobs cancellable, `started_by_home_assistant: true` |
| `services.py` | Log and swallow a tracking failure after a successful start | Tracking failure does not mask the start |
| `tests/test_execution.py` | Regression tests for button tracking, cancel and tracking failure | Regression test fails without the fix |
| `tests/test_lifecycle.py` | Completion event of a button-started job reports Home Assistant as origin | Event criterion |

## Failure modes and rollback

- A store write failure during tracking — logged at warning level, the job identifier is still
  returned and the press still succeeds. Rollback is a single-file revert of `services.py`.
- Registry pressure from frequent presses — bounds are unchanged; recorded as a residual risk in the
  ticket.

## Security and privacy review

- Credentials: none touched; the helper handles identifiers only.
- Sensitive payloads: the projection stays `job_id`, `kind`, `path`, `started_at`; arguments and
  results are never persisted, and the warning log carries only the job identifier.
- Permissions: unchanged.
- Network exposure: unchanged; no additional request.
