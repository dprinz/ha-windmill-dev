## Failure modes and rollback

- A queue larger than `MAX_JOB_ROWS` fails the poll closed — accepted, graceful and retried;
  the transport cap would reject the payload first anyway.
- A smaller `RUN_PAGE_SIZE` shortens the observed completion window per poll — mitigated by
  `MAX_RUN_PAGES` and the 60 s poll interval; the watermark still prevents missed events
  inside the window.
- Rollback is a single revert; no storage, option or entity schema changes.

## Security and privacy review

- Credentials: untouched.
- Sensitive payloads: the parsed projection is unchanged; a larger accepted row count never
  widens per-row parsing, and `args`/`result`/`logs` stay discarded.
- Permissions: unchanged; no new endpoint and no new scope.
- Network exposure: strictly fewer requests per poll in the common case.

## Plan changes

- 2026-08-04: scope widened from probe-only to probe plus polling after reading the upstream
  union — a probe-only fix would have enabled the feature into a permanently failing
  coordinator. Recorded in the ticket's "Why".
- 2026-08-04: added job-ID deduplication in `_async_observe`. Not in the original file table:
  reviewing the page walk showed that upstream's ignored `offset` lets a later page repeat an
  earlier one, so a busy workspace reported up to three times its real running/queued count.
  The smaller `RUN_PAGE_SIZE` of this change makes repeated pages more likely, so the fix is
  required here; WMHA-0039 still tracks avoiding the useless requests themselves.
