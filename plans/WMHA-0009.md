# Plan for WMHA-0009

## Current state verified

- WMHA-0008 stores explicit selections in `entry.options["runnables"]` and resolves them into
  availability, script hash, optional flow version and a bounded parameter projection.
- `custom_components/windmill/api.py` had a GET-only transport, so execution required generalizing
  the bounded request path without changing its limits.
- `docs/research/windmill-api-contract.md` records the four asynchronous execution endpoints
  (`jobs/run/p`, `jobs/run/h`, `jobs/run/f`, `jobs/run/fv`), the `201 text/plain` job identifier and
  the rule that synchronous `run_wait_result` variants stay out of scope.
- ADR-0001 keeps script and flow execution `not_applicable` in the capability matrix, so
  authorization has to be established at operation time rather than inferred from a read probe.

## Design decisions

1. **One typed action instead of two.** `windmill.run` takes the config entry, the kind, the path
   and optional arguments. The kind is an explicit field, so the contract stays unambiguous without
   duplicating validation across two actions.
2. **Selection is the authorization gate.** The action resolves the path through the runnable
   coordinator. An unselected, unavailable or schema-unsupported runnable is rejected with a
   `ServiceValidationError` before any request is built.
3. **Arguments are validated locally first.** Unknown, missing, mistyped, out-of-enum, oversized and
   non-JSON-compatible arguments fail before the network call. Booleans never satisfy numeric
   parameters.
4. **Addressing never changes implicitly.** A `pinned` selection is executed by hash or version. If
   the resolved runnable exposes neither, the action refuses instead of silently running the
   deployed head.
5. **Responses stay bounded.** The action returns only `{"job_id": ...}` after validating that the
   response is a UUID. Job results, logs and arguments are never read back.
6. **Buttons are opt-in and additive.** The `runnable_buttons` option, disabled by default, adds one
   button per selected parameterless runnable. The action remains the complete interface.
7. **The started-job registry stays with WMHA-0010.** This ticket returns the job identifier but does
   not track it; bounded tracking and cancellation belong to the lifecycle ticket.

## Failure modes and rollback

- A selected runnable disappears between resolution and execution — Windmill answers `404` and the
  action raises a distinct `runnable_missing` error.
- The token loses run permission — `403` becomes `insufficient_permission`, `401` becomes
  `invalid_auth` and triggers the normal reauthentication path on the next coordinator refresh.
- Windmill returns something other than a job identifier — the client raises a protocol error and
  no job identifier is fabricated.
- Rollback is one ticket commit; removing the action leaves discovery and selection intact.

## Security and privacy review

- Credentials: execution uses the shared bearer header; no token ever appears in a URL.
- Sensitive payloads: arguments are sent but never stored, logged or returned. The response keeps
  only the job identifier.
- Permissions: least privilege is preserved because only explicitly selected runnables are
  addressable.
- Network exposure: exactly one bounded POST per action call.
