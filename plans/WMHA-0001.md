## Failure modes and rollback

- Upstream OpenAPI and deployed behavior diverge — mark the behavior unknown, cite both sources, and require a sanitized instance experiment before implementation.
- Edition or permission semantics are not stated normatively — avoid inventing a contract; model the capability as optional and record the unresolved validation need.
- Upstream source changes during research — pin inspected source links to an immutable commit or release tag and record the verification date.

## Security and privacy review

- Credentials: no real tokens or private instance URLs will be used or stored.
- Sensitive payloads: examples and proposed fixtures will contain only obvious fake values and bounded metadata.
- Permissions: each capability will be mapped to the least privilege established by primary sources; administrative monitoring remains optional.
- Network exposure: research is read-only against public primary sources; no user or production instance is contacted.
