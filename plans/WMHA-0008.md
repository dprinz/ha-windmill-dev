# Plan for WMHA-0008

## Current state verified

- `custom_components/windmill/api.py` probes the script and flow listings for the capability matrix
  but has no runnable model, no detail read and no schema projection.
- WMHA-0004 owns the options flow, which currently has a single feature step. Selection therefore
  has a natural home in a second options step.
- The pinned upstream types
  ([`scripts.rs`](https://github.com/windmill-labs/windmill/blob/v1.775.2/backend/windmill-types/src/scripts.rs)
  and [`flows.rs`](https://github.com/windmill-labs/windmill/blob/v1.775.2/backend/windmill-types/src/flows.rs)
  at v1.775.2, verified 2026-08-02) show that `ListableScript` carries `hash`, `path`, `summary`,
  `archived`, `kind`, `language` and draft markers but **no schema**, and that `ListableFlow`
  carries `path`, `summary`, `archived` and draft markers but neither schema nor version. Input
  schemas therefore require the detail endpoints, and the listings alone cannot answer whether a
  runnable's arguments are supported.
- `docs/research/windmill-api-contract.md` records the detail and execution addressing endpoints
  and limits the safe schema projection to parameter name, JSON type, required flag and bounded
  enum values.

## Design decisions

1. **Discovery is bounded and never stored wholesale.** Listing walks at most three pages of 100
   rows per kind and keeps only kind, path and summary. Archived and draft-only rows are dropped
   because they are not runnable.
2. **Selection is a small explicit list in options.** `entry.options["runnables"]` holds at most 25
   entries of `{kind, path, mode}`. Nothing is selected by default, so no runnable can become
   executable without a user action.
3. **Selection is keyed by kind and path.** Pagination order, summaries and hashes may change
   without affecting the stored selection, and a reload restores exactly the same set.
4. **Resolution is a separate, slower coordinator.** Every 30 minutes the selected runnables are
   resolved through their detail endpoints into availability, current script hash, optional flow
   version and the bounded parameter projection. A missing or denied runnable becomes unavailable
   and recovers by itself when it returns.
5. **Argument support is decided before execution exists.** The schema projection accepts only
   `string`, `number`, `integer`, `boolean`, `array` and `object` parameters. Anything else, a
   malformed schema or a schema with combinators marks the runnable as unsupported with a bounded
   reason, which WMHA-0009 must honor before enabling execution.
6. **Script pinning is supported, flow pinning only when a version is exposed.** `ListableScript`
   and the script detail both carry the hash, so pinned scripts are safe today. The pinned flow
   version is not present in the verified flow types, so a flow keeps `latest` unless its detail
   response actually exposes a numeric `version`. The mode is always stored explicitly and never
   changed implicitly.

## Selection model

| Field | Meaning |
| --- | --- |
| `kind` | `script` or `flow` |
| `path` | validated Windmill path, the stable identity |
| `mode` | `latest` follows the deployed head; `pinned` freezes the script hash or flow version |

| Observation | Resolution result |
| --- | --- |
| Runnable exists | available, with current hash or version and the parameter projection |
| Runnable removed or renamed | unavailable with reason `missing`, recoverable on return |
| Detail read denied | unavailable with reason `unauthorized` |
| Detail read fails temporarily | the whole refresh fails, so every selection keeps its last state |
| Schema unsupported | available but marked unsupported with a bounded reason |
| Pinned script or flow | the resolved hash or version is the stored one, not the deployed head |

## Failure modes and rollback

- A workspace has thousands of runnables — discovery stops after the bounded page walk and the
  selection form says so instead of loading everything.
- A selected runnable disappears — it stays in the options, resolves as unavailable and recovers
  automatically.
- Discovery is denied for one kind — only that kind is missing from the picker.
- A path contains unsafe characters — it is rejected before any request is built.
- Rollback is one ticket commit; the options key is additive and an entry without it behaves as
  before.

## Security and privacy review

- Credentials: all reads use the shared bearer header.
- Sensitive payloads: only kind, path, summary, hash, optional version and the bounded parameter
  projection are retained. Content, lock files, extra permissions, drafts, descriptions, defaults,
  examples and every other schema value are discarded in the client.
- Permissions: read-only discovery; a denial disables selection for that kind only.
- Network exposure: bounded listings during the options flow and at most one detail read per
  selected runnable every 30 minutes.

## Open questions

- Whether the flow detail response exposes a numeric version cannot be settled from the verified
  types alone, so flow pinning stays conditional on the field actually being present.
- Whether a summary can contain sensitive text is a workspace convention; summaries are shown in
  the picker but never stored in entity state.
