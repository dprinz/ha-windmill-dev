# Plan for WMHA-0002

## Current state verified

- WMHA-0001 is accepted in commit `603dc3a`; `whoami` is the canonical authenticated workspace-validation call.
- The repository has no Home Assistant component, Python project metadata, production code or automated integration tests.
- Home Assistant `2026.7.4` is the current stable validation target; it requires Python 3.14, which is available locally.
- The official config-flow guidance requires UI setup, test-before-configure and collision-safe duplicate handling.
- Home Assistant's current unique-ID guidance rejects a mutable URL as a unique ID. This ticket will therefore compare the normalized base URL plus workspace directly to existing entry data and leave `ConfigEntry.unique_id` unset until Windmill exposes a stable instance identifier. This still prevents duplicate instance/workspace combinations without encoding the token or violating the URL guidance.

## Dependency decision

- Runtime: no new package. The client accepts an `aiohttp.ClientSession`; the Home Assistant adapter injects Home Assistant's shared session.
- Test only: `pytest-homeassistant-custom-component==0.13.348` is required to exercise the custom integration through real Home Assistant 2026.7.4 interfaces rather than local stubs. Ruff, mypy and coverage tooling are development-only and pinned in the lockfile.

## Failure modes and rollback

- Home Assistant API drift — pin tests to the current stable release and record the source date; update deliberately in a later ticket.
- Windmill returns an unexpected `whoami` body — raise a protocol error without logging the body or token.
- Setup-time connection failure — use `ConfigEntryNotReady`; authentication failure uses `ConfigEntryAuthFailed`; permanent permission/protocol failures use `ConfigEntryError`.
- Duplicate identity changes with a base-URL migration — reconfiguration is a later ticket; do not create an unsupported URL-derived Home Assistant unique ID now.

## Security and privacy review

- The token is stored only in config-entry data and sent only in the `Authorization` header.
- URL normalization rejects user-info, query, fragment and non-HTTPS remote endpoints; TLS verification remains enabled.
- Exceptions and logs contain only typed categories, not response bodies, tokens or authorization headers.
- No real Windmill or Home Assistant system is contacted by automated tests.
