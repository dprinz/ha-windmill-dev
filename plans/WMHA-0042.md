# Plan for WMHA-0042

## Current state verified

- `WMHA-0040` verified that Windmill materializes the next occurrence of a schedule as a queued
  job with a future `scheduled_for`, and that `clear_schedule` removes it on disable, edit and
  delete.
- `QJ_FIELDS` selects `scheduled_for`; the completed half selects `null as scheduled_for`.
- `WindmillJob` does not carry `scheduled_for` yet, and `_parse_job` ignores it
  (`api.py:1395`).
- `WMHA-0041` shipped the per-runnable read and `RunnableRunState`, so the row that carries the
  answer is already fetched by both tiers.

## Failure modes and rollback

- **A pending job read as a future run.** A queued job waiting for a worker also carries a
  `scheduled_for`, in the past. Only a queued row whose `scheduled_for` is ahead of the current
  time is a next run, and a running row is never one.
- **A frozen value.** `next_run` must be derived fresh from every observation and must not be
  persisted, or a schedule disabled while Home Assistant was down would still be announced.
- Rollback is a revert; the sensor is additive.
