## Live checks

### A. Restricted/granular-scoped token (closes check 1)

1. Validate the ticket assumption: mint a granular-scoped token on the disposable instance
   (UI or `POST /api/users/tokens/create`-style endpoint), scopes:
   `users:read`, `workspaces:read`, `jobs:read`, `jobs:write`,
   `jobs:run:scripts`, `jobs:run:flows`, `scripts:read`, `flows:read`.
2. Onboarding: `whoami` + workspace list with the restricted token via the client
   (`async_validate`, `async_list_workspaces`) — expect 200 per the contract.
3. Execution: disposable Deno script and flow; run by path and by pinned hash/version
   through `async_run_runnable`; record status codes and job UUIDs.
4. Cancellation: long-running disposable script cancelled via `async_cancel_job` with the
   restricted token; expect the contract's `jobs:write` + per-job authorization behavior.
5. Capability five-state mapping: run `async_discover_capabilities` with the restricted
   token and record which probes flip to `unauthorized` (detailed health expectation below).

### B. Detailed health with granular-scoped token (closes check 2)

Contract prediction (pinned `scopes.rs`/`auth.rs`): no `health` scope domain exists, so a
granular-scoped token fails scope middleware before the handler. Probe
`GET /api/health/detailed` with (a) the granular-scoped token, (b) an unscoped non-admin
workspace token, and record actual status (200/401/403/404) against the prediction.

### C. Busy workspace (closes check 4 from the matrix, WMHA-0007)

Generate real job traffic on the disposable workspace: a batch of scripts that succeed, one
that fails, one that is cancelled. Observe through the client's bounded job listing
(`async_list_jobs`-style projection): dedupe by UUID, bounded pages, watermark behavior,
allowlist-only fields (no args/results/logs retained).

### D. Cloud tenant (check 3)

## Plan changes

Record material deviations here during implementation.

- Compose setup was a minimal derivation of the official `docker-compose.yml` at `v1.775.2`
  (db + server + 2 default workers + 1 native worker), binding the server directly to
  `127.0.0.1:8000` instead of the Caddy reverse proxy — fewer pulls, same server/API surface.
- `POST /api/workspaces/create` rejects a `username` field on this version ("username is not
  allowed when username creation is automated"); the workspace was created without it.
- First probe run also showed the `runs` capability probe failing once seconds after
  workspace creation; reproduced as transient (succeeds immediately and after delay on
  repeat) — recorded as the known upstream propagation race, not a client defect.
- One genuine contract precision found: granular-scoped tokens get `400` (not `401`/`403`)
  on `/api/health/detailed`; the client surfaces this as `unsupported` instead of
  `unauthorized` → new backlog ticket WMHA-0030.
