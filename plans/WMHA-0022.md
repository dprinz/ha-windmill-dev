# Plan for WMHA-0022

## Current state verified

- `WindmillRunEventEntity._handle_coordinator_update` (`event.py:36`) reads
  `self.coordinator.data.new_events` on every listener notification, including notifications that
  follow a failed refresh, where `coordinator.data` is still the snapshot of the last successful
  poll.
- `WindmillRunSnapshot` (`coordinator.py:319`) is a frozen dataclass built fresh in `_observe` for
  every successful poll, so snapshot identity is a reliable "this is a new observation" signal.
- `CoordinatorEntity.async_added_to_hass` only registers the listener; it does not invoke the
  handler. So an entity added after a refresh has published nothing yet, and its first notification
  may carry a snapshot that already contains events — which is why a snapshot-identity check alone
  would not be enough.

## Proposed changes

| File or component | Change | Acceptance criterion |
| --- | --- | --- |
| `event.py` | Publish only for a fresh observation: skip when `coordinator.last_update_success` is false or when the snapshot was already published by this entity, and still delegate to `super()` so availability handling is untouched | No republication after a failed poll; availability intact |
| `tests/test_runs.py` | Regression test: successful poll with a completion, failed poll, successful poll without a completion; the entity state must not move | Regression criterion |

## Failure modes and rollback

- Over-suppression, where a real completion is never published — guarded by the existing tests for
  new completions, several completions per poll, ordering and deduplication across reloads.
- Rollback is a single-file revert of `event.py`.
